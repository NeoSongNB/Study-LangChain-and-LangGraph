## 2. 运行方式

在当前示例目录中运行选定文件，例如：

```powershell
python "08_使用values流观察Agent完整状态.py"
```

`environment.yml` 提供原课程环境清单，其中 LangChain 为 1.2.3、LangGraph 为 1.0.6。
调用模型的脚本通过 `.env` 读取 `ARK_API_KEY`；模型名称与接口地址保留原配置，需要账号实际支持。
这些是独立演示文件，部分文件在模块顶层发起请求，不宜把所有脚本一起 import 或批量运行。

MCP 示例额外依赖 `mcp`，客户端还需要 `langchain-mcp-adapters`；原环境清单未列出这两个包。
若环境尚未安装，可在对应环境执行 `python -m pip install mcp langchain-mcp-adapters`，具体版本需与课程环境兼容。

- 20 + 21：直接运行 21，客户端会自动启动 20 的 stdio 子进程。
- 22 + 23：先在一个终端运行 22，保持服务启动，再在另一个终端运行 23。
- stdio 模式的 stdout 用于协议通信，服务端调试日志应写 stderr。

## 3. 对照学习与已有问题

- 01 与 10：`agent.invoke` 返回状态字典；`llm.invoke` 返回模型消息。
- 05 / 06 / 08 / 09：区分 Agent 消息片段、模型消息片段、完整状态、节点增量。
- 07、08、09、11 等示例虽然有 `thread_id`，未配置 checkpointer，因此不会自动跨调用保存历史。
- 12 与 13：对照多工具决策和工具内部合并业务流程；时间点差值包含模型与网络开销。
- 14、15：原逻辑基本一致，保留两份。工具消息可能被标成“最终回复”，`tools` 的后置分支通常被前面的 `messages` 判断覆盖；已在原位置说明。
- 16 与 main：分别演示检查点状态查看、同一线程连续对话；内存记忆不会跨进程保留。
- 17 与 18：Callbacks 事件不等同于 Agent 中间件。17 原回调对输入输出类型的假设可能引发回调报错，详见旁注；18 直接演示 Agent 生命周期边界。
- 19：原工具名读取位置和异常分支返回类型有问题，保留原语句并在旁边提供修复建议；本次未将其改写成另一套实现。
- 天气与定位工具均使用模拟数据，日志中的“实时天气”不表示实际接入气象服务。
- 14、15 的 `reasoning_content` 仅在服务端实际返回时可读，不保证存在。

本次主要修改文件名和注释。为配合重命名，21 的服务端路径改为相对脚本定位，并使用当前 Python 解释器。
原 24 份脚本及原 README 已保存在 `原始代码备份_注释前.zip`；备份不含 `.env`。
本次执行静态语法检查及代码差异核对，未调用模型或启动 MCP 服务进行端到端验证。
